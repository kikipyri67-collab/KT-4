1. SSH и firewall
Даже если firewall разрешает порт 22, подключиться извне нельзя, если SSH слушает только 127.0.0.1:22. Firewall лишь пропускает пакет, но сервис должен ещё принимать соединения на этом адресе.
2. Выход web42ns в интернет
Для выхода в интернет namespace нужны маршрут по умолчанию, включённый forwarding на хосте и NAT (MASQUERADE). Адрес 10.200.0.2 является внутренним, поэтому напрямую через интернет работать не будет. MASQUERADE заменяет его на внешний IP хоста.
3. Docker и порт 8080
Трафик на опубликованный Docker-порт не проходит через обычную цепочку INPUT. Docker перенаправляет его через PREROUTING и FORWARD в контейнер. Поэтому отсутствие разрешения в INPUT и ufw deny 8080 не блокируют такое подключение.
4. Прямой порт 8080 или nginx
При прямом доступе к :8080 приложение открыто наружу, а часть возможностей reverse proxy теряется. Например, становится сложнее централизованно настроить HTTPS и направлять разные домены на разные приложения. При использовании nginx наружу открыт только nginx, а приложение остаётся внутренним backend'ом.
